## 2. 无效尝试与原因（下次直接跳过）

| 尝试 | 为什么无效 |
|---|---|
| 批量 `Unblock-File` 清下载标记 | 文件根本没有标记；提示文案里的「Internet」是**外壳判定的措辞**，不是文件属性 |
| 查 EA / `System.Zone.Identifier` | 同上，方向错 |
| 改 `Zones\*` 的 `1806` | 它管「区域策略」，本机文件被外壳判定的路径不受它影响 |
| 改 `ProtocolDefaults\file` | `file=3` 是 Windows 默认行为，不是异常 |
| 删 `ScanWithAntiVirus` | 非根因；删除后症状不变 |
| 退出安全软件复测 | 非杀软行为 |
| `IAttachmentExecute` 直接问策略 | 该 CLSID 在本机不暴露此接口 |
| 在沙箱内做移动/删除复现 | **最大的坑**：我的进程也是 Low IL，与目标同级，必然成功 |

## 3. 造成排查缓慢的三个关键失误

1. **锚定效应**：第一轮就接受了「Internet 标记」这个解释，之后所有证据都往这个方向解释（confirmation bias）。
2. **验证环境自相矛盾**：用被沙箱污染的进程去验证沙箱故障 —— 测试必然通过，结论必然错误。
3. **忽略最直接的元数据**：`icacls` 的 `Mandatory Label` 一行从头到尾都在那里，却直到第 6 轮才被查看。**它能一眼看出 Low**。

## 5. 经验条目（供下次直接套用）

| 编号 | 经验 |
|---|---|
| L1 | 桌面/文档等用户目录**不要作为带沙箱工具的工作区** |
| L2 | 遇到「某类操作全面失灵 + 安全提示」，**先 `icacls <目录>` 看 `Mandatory Label`** |
| L3 | 弹窗文案里的「Internet/不受信任」是判定结果的**措辞**，不等于文件上有下载标记 |
| L4 | 沙箱内进程不能用来复现沙箱故障（同级写入会「假通过」） |
| L5 | 改注册表前先备份，改完不复现就**还原**，避免叠加副作用 |
| L6 | 相同症状优先搜索：往往已有现成案例，命中一次胜过十次猜测 |
| L7 | 排查产物一律记清单、事后清理，避免污染用户目录 |
