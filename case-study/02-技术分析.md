# 技术分析：低完整性（Low IL + NW）如何造成「文件可能有害」与「无法移动」

配套：`01-安全报告.md`（结论）、`03-试错日志.md`（过程）

---

## 1. 先补一个 Windows 概念：完整性级别

Windows 除了「用户 / SID 权限」外，还有一层**强制访问控制**：每个进程和每个对象（文件、目录、注册表键）都有一个**完整性级别（Integrity Level, IL）**。

| 级别 | 数值 | 典型对象 |
|---|---|---|
| 不受信任 Untrusted | 0x0000 | 沙箱化进程 |
| 低 Low | 0x1000 | 浏览器渲染进程、**被降级的沙箱工作区** |
| 中 Medium | 0x2000 | 普通用户进程、用户创建的文件（默认） |
| 高 High | 0x3000 | 管理员提权后的进程 |

强制策略是「**不能向上写**」：低完整性进程不能写中完整性对象。

对应标签在 `icacls` 里长这样：

```
Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)
```

- `Low` —— 低完整性（正常应为 Medium，或干脆无标签，默认即 Medium）；
- `(OI)(CI)` —— 对象继承 + 容器继承，**会向下传播**；
- `(NW)` —— No-Write-Up，禁止向更高或相等完整性方向「写」。

### 关键点：它和 NTFS 权限是两套东西

`Everyone: 拒绝 删除子文件夹及文件` 属于**传统 DACL 权限**；`Low ... (NW)` 属于**强制标签**。两者互不覆盖：

- 即使你的账号对该目录有 `FullControl`（DACL 允许），
- 只要标签是 `(NW)`，**中完整性进程的写入依然被拒绝**。

这就是「权限看起来完全正常、文件却移不进去」的原因。

## 2. 沙箱实际做了什么

从安全软件 HIPS 日志抓到的真实命令行（已脱敏）：

```
<install>\DeepSeek Harness.exe ... @deepseek-ai/dsh-subprocess-local/lib/runner.js
  -- <install>\DeepSeek Harness.exe ... @deepseek-ai/dsh-sandbox-windows-acl/lib/runner.js
     --workspace C:\Users\<user>\Desktop\<project>
     --temp C:\Users\<user>\AppData\Local\Temp\dsh-xxxxxx
     --mode workspace-write
     --write-sid S-1-4-<redacted>
     -- C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe -NoLogo -NoProfile ...
```

可以读出三件事：

1. 该工具的每条命令都要经过 `dsh-sandbox-windows-acl` 这层适配器；
2. 它按 `--workspace` 指定的目录施加隔离；
3. 它创建/使用合成 SID（`S-1-4-*`，`S-1-4` 为「非唯一权威」，典型用于受限令牌）。

工作区根目录被施加的隔离包括：

| 隔离手段 | 落地形式 | 对用户的可见影响 |
|---|---|---|
| 写权限收敛 | `S-1-4-*` 允许写 | 无（沙箱自己用） |
| 防删除 | `Everyone: 拒绝 删除子文件夹及文件` | 很小（用户另有 FullControl） |
| **防外溢** | **`Low` + `(NW)` 强制标签** | **本次全部症状** |

### 为什么「工具碰过的文件夹都出事」

因为强制标签带 `(OI)(CI)`：一旦工作区根目录被降到 Low，**它下面已存在和之后新建的所有内容全部继承 Low**。工作区是桌面，就等于把整张桌面交给低完整性。

## 3. 症状如何从这一个原因推导出来

| 症状 | 推导 |
|---|---|
| 双击文件弹「可能对你的计算机有害 / Internet 安全设置阻止」 | 低完整性内容被外壳归入「不受信任来源」，打开动作触发安全确认（同类现象见 §6） |
| 文件夹却能正常打开 | 打开目录是「读」，不涉及向上写 |
| 文件移不进桌面、复制报错 | 中完整性进程（资源管理器）向 Low 对象写入 = 向上写 = 被 `(NW)` 拒绝 |
| 快捷方式图标变白板 | 图标缓存（中完整性）读/更新 Low 对象受限，退回默认图标 |
| 打开 .png/.cmd 不弹、只有 .lnk 弹 | 附件管理器按「文件类型风险」分级，快捷方式被列入高风险类型，先撞上 |
| 安全软件 HIPS 反复告警 | 独立事件：沙箱用无窗口 PowerShell 执行命令，命中通用的「隐藏窗口执行脚本」启发式 |

## 4. 三个「看起来像原因」的假象

### 4.1 Internet 标记（MOTW）—— 排除

| 检测 | 结果 |
|---|---|
| 遍历桌面 7,026 个文件查 `Zone.Identifier` 数据流 | 131 个有标记，全部是真实下载件（论文 PDF、代码仓库压缩包、聊天工具接收的文档） |
| `fsutil file queryea`（扩展属性） | 无 |
| Shell 属性 `System.Zone.Identifier` | 空 |
| `Get-Item -Stream *` | 只有 `:$DATA` |

结论：**该工具生成的文件从未带过下载标记**；「解除锁定 / `Unblock-File`」从一开始就不可能修好这个问题。

> 附带事实：MOTW 会随解压、复制「传染」，所以一个目录里只要躺着一两个下载物，就会给人「整个文件夹有毒」的错觉。

### 4.2 `file = 3`（ZoneMap 协议映射）—— 排除

```
HKCU\...\Internet Settings\ZoneMap\ProtocolDefaults
    file = 3
```

一度被当作元凶（「本地文件被映射到 Internet 区域」）。实测把它改成 0 后，`MapUrlToZone("file:///C:/...")` 仍返回 Zone 3，且弹窗不变。

进一步确认：**`file = 3` 是 Windows 的正常默认**（IE 家族历来把 `file://` 按 Internet 区域解析）。此判断是本次排查中的一次误判，已还原。

### 4.3 `ScanWithAntiVirus = 3`（附件管理器强制扫描）—— 排除

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\Attachments
    ScanWithAntiVirus = 3
```

该值确属非默认（正常不存在或为 1/2），理论上会让「打开文件前先交杀软扫」。但删除该值并重启后症状仍在，故排除。

## 5. 为什么我的复现实验全部「成功」（最关键的坑）

排查过程中，我用工具自带的 PowerShell 做过这些测试，全部成功：

- 桌面新建文件 / 删除文件；
- 桌面新建目录 / 删除目录；
- 在带「拒绝子项」的目录里新建、删除；
- 从子目录移动文件到桌面。

**这些测试全部无效**，原因：

> 我的命令本身就跑在沙箱里，进程令牌也是 **Low 完整性**，与那些文件**同级**。同级写入不被 `(NW)` 限制，所以我测什么都通过；而用户的资源管理器是 **中完整性**，向上写必然失败。

**教训**：在沙箱内诊断「沙箱造成的故障」，不能用沙箱内的进程去验证 —— 它会自动「通过」。必须用外部/中完整性进程（资源管理器、管理员终端）验证。

## 6. 同类案例对照

微软 Q&A 上有一例症状几乎完全相同：

> 「我放在桌面上的数个快捷方式及自己放的 .bat 文件双击打开时均会弹出『打开文件-安全警告』，而直接从文件夹中选择它们的 .exe 打开则不会弹出。」

顾问给出的解决命令正是：

```powershell
icacls C:\Users\<用户名>\Desktop /setintegritylevel "(OI)(CI)M"
```

—— 与本机的实际修复方式一致，相互印证。

## 7. 置信度

| 结论 | 置信度 | 依据 |
|---|---|---|
| 桌面处于 Low 完整性 + NW | **确定** | `icacls` 直接读出 |
| 标签递归继承到所有子项 | **确定** | 逐项 `icacls` 结果一致 |
| 沙箱是施加者 | **高** | 标签位置 = 工作区根、继承范围 = 工具触及路径、命令行参数吻合、时间线吻合 |
| Low IL 直接导致该弹窗文案 | **中高** | 症状一致性 + 同类案例；未逐层抓取外壳内部判定 |
| 修复后症状消失 | **确定** | 用户实测恢复 |

标注「中高」的部分，留待下次用 ProcMon 抓 `shell32` 的判定过程可完全坐实。

## 8. 下次遇到：3 分钟定位流程

```powershell
# ① 第一件事：看强制标签（低完整性会直接印在这行）
icacls "$env:USERPROFILE\Desktop" | Select-String "Mandatory"

# ② 看自己的令牌级别，判断实验是否可信
whoami /groups | Select-String "Mandatory Label"

# ③ 确认文件是否真的带下载标记（排除 MOTW 路线）
Get-ChildItem "$env:USERPROFILE\Desktop" -Recurse -File |
  Where-Object { Get-Item $_.FullName -Stream Zone.Identifier -ErrorAction SilentlyContinue } |
  Select-Object -First 10 FullName

# ④ 修复（管理员）：把整个桌面恢复为中完整性
icacls "$env:USERPROFILE\Desktop" /setintegritylevel "(OI)(CI)M" /T /C

# ⑤ 校验
icacls "$env:USERPROFILE\Desktop" | Select-String "Mandatory"   # 应无 Low
```

判断口诀：

- `Mandatory Label` 里有 `Low` → **就是它**，直接修，别再查标记；
- 没有 `Low`、也没有 `Zone.Identifier` → 再往「附件管理器策略 / 安全软件外壳钩子」方向查；
- 只有在**外部进程**（资源管理器、管理员终端）里才能复现真实故障。

## 9. 修复命令备忘

```powershell
# 常规修复（管理员）
icacls "$env:USERPROFILE\Desktop" /setintegritylevel "(OI)(CI)M" /T /C

# 若提示「拒绝访问」，先夺回所有权再修
takeown /f "$env:USERPROFILE\Desktop" /r /d y
icacls "$env:USERPROFILE\Desktop" /reset /T /C
icacls "$env:USERPROFILE\Desktop" /setintegritylevel "(OI)(CI)M" /T /C
```

参数说明：`/T` 递归、`/C` 遇错继续、`M` = Medium（中完整性）。
